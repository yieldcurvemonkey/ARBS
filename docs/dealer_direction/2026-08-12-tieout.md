## 0. The direction mapping, hand-traced before anything was measured

A sign error in a pre-registration on this project survived until an independent
reviewer noticed two stated mechanisms could not both be true, so the mapping was
confirmed on worked examples with printed arithmetic **before** any agreement
number existed. `scratch/tieout_trace.py`, **41 checks, 0 failures**. It calls the
frozen `classify_unit` and the new `conventions` / `upfront` directly — no
re-implementation of either side.

```
[outright_above_mid] kind=OUTRIGHT
    traded_pct=[4.05]  mid_pct=[4.0]
    OLD  s2m = 4.999999999999982 bp  -> dealer_direction = 'RECEIVED'  (RATE_VS_MID)
    NEW  q = (1.0,)  P_traded = 405.000000 bp  P_mid = 400.000000 bp
    NEW  dev = 5.0 bp -> dealer_side = 1 (DEALER_RECEIVED)

[curve_above_mid] kind=CURVE                 legs maturity-ordered: 0 = front
    traded_pct=[4.0, 4.2]  mid_pct=[4.0, 4.1]
    OLD  s2m = 10.000000000000053 bp -> 'RECEIVED'  (SPREAD_VS_MID)
    NEW  q = (-1.0, 1.0)  P_traded = 20.0  P_mid = 10.0  dev = 10.0 -> +1

[fly_above_mid] kind=FLY                     index 1 = belly
    traded_pct=[4.0, 4.2, 4.3]  mid_pct=[4.0, 4.15, 4.3]
    OLD  s2m = 9.999999999999964 bp -> 'RECEIVED'  (FLY_VS_MID)
    NEW  q = (-1.0, 2.0, -1.0)  P_traded = 10.0  P_mid = 0.0  dev = 10.0 -> +1

[upfront_dealer_bought_itm_payer] npv_pay=100.0 U=5.0 dv01=10.0
    OLD  dealer_bought = (U < |npv|) = True; itm_side = PAID  -> PAID
    NEW  dev = -npv/dv01 = -10.0 bp; u = 0.5 bp; z = |dev|-u = 9.5 bp
    NEW  edge = sign(dev)*z = -9.5 -> dealer_sign = -1 (DEALER_PAID)

[upfront_dealer_sold_itm_payer]  npv_pay=100.0 U=200.0 dv01=10.0
    OLD  dealer_bought = False -> RECEIVED
    NEW  z = 10 - 20 = -10; edge = +10 -> dealer_sign = +1 (DEALER_RECEIVED)
```

The mapping is therefore `dealer_sign == +1  ⟺  "RECEIVED"` and
`-1 ⟺ "PAID"` under **both** rules, on all four structure shapes and both
upfront branches. Both directions of the upfront branch were traced (ITM-payer
and ITM-receiver × dealer-bought and dealer-sold), because that rule has two
negations that must not cancel.

The one **deliberate** divergence:

```
[outright_exact_tie]
    OLD  s2m = 0.0 -> 'PAID'   (`RECEIVED if s2m > 0 else PAID` has NO zero branch)
    NEW  dealer_side(0.0) = 0  (0 = no call)
```

### Why `b0` is forced to zero in the logic tie-out

`p = sigmoid((dev - b0) / tau)`. The fitted `b0` on the legacy curve is
≈ −0.28 bp globally and −0.42 bp at 2Y-3Y (§4). Under a fitted `b0`,
`p > 0.5 ⟺ dev > −0.28`, while the frozen rule is `dev > 0`:

```
    with the measured Barchart b0 = -0.4836 (F-20): dev = -0.20 bp
      -> p = 0.9008 -> RECEIVED   <- OPPOSITE of the old rule,
                                     by CALIBRATION not by logic
```

That is the ≥34 pp label shift D11 says a correct system cannot avoid, and a gate
that counts it as disagreement could only be passed by a system reproducing the
bias. So the logic tie-out uses `b0 = 0`, under which
`p > 0.5 ⟺ conventions.dealer_side(dev) > 0` — the task's "`RECEIVED if p > 0.5`"
formulation applied to the same decision rule the old code applies:

```
    b0=0:  dev = -1e-9 -> p < 0.5 -> PAID       dev = +1e-9 -> p > 0.5 -> RECEIVED
```

`tau` is still the fitted one, because `tau` sets the ABSTAIN band and nothing
else. The fitted-`b0` effect is reported separately in §6, and **the curve effect
holds `b0 = 0` on both curves** so that measurement varies one thing too.

## 1. What was run, and what was held constant

**Reference.** A fresh dry-run of the frozen pipeline, **not** the persisted
`arbs_stir_direction_v1` (T-3: those rows came off the `_v2` tape and rateslib
2.1.1). The driver imports `run_calibration` / `classify_units` /
`run_classification` from `backfill_stir_direction.py` directly rather than
calling `main()`, because `main()` calls `ensure_schema(conn)` — a write against
the production tape DB. **Nothing was written to the database**; the psycopg2
session is opened `readonly=True`.

Calibration windows are the production ones verbatim from
`scripts/backfill_dealer_ladder_window.sh` (monthly chunk, calibration window
ending the day before the chunk, so no day's tick stats see its own future).

| held constant | how |
|---|---|
| **unit set** | `stir_flow.trade_selection.build_units` filtered by `is_excluded_unit`, then *wrapped* into `dealer_direction.types.Unit`. The new package's own universe module is not consulted — the join key must be the old system's unit definition. 37,905 units, 0 unmatched either way. |
| **upfront routing** | `Unit.upfront` from the OLD `trade_selection.resolve_upfront`, so `want_npv` fires on exactly the units the old classifier called off-market. New-native upfront resolution is out of scope for the logic tie-out, deliberately. |
| **instant** | `stir_flow.pricing.snap_timestamp` passed explicitly as `price_unit(instant=...)`, and **asserted** equal to `snapshot.snap_instant(unit.clocks.pricing)` on every one of the 37,905 units (the assert is in the driver and never fired). |
| **curve** | Not merely "the same source" — the new Barchart pricer's handle cache is **seeded from the old pricer's**, so both systems price against the *same* `rl.Curve` objects. Verified per day: handles after the new pass == handles before, i.e. **zero extra builds**. |
| **lifecycle** | `is_lifecycle=False` on every unit. The old system has no lifecycle concept and `upfront.classify(is_lifecycle=True)` negates orientation, so letting the new side detect lifecycle rows would manufacture inversions that are a scope difference, not a logic difference. |
| **capped** | `exclude_capped` left at its default (`CAPPED_UPFRONT_IS_UNSCALED = False`), i.e. capped prints are classified, as the old code does. |

The new package runs on the legacy curve because `midprice.SessionBranchPricer`
takes the source as a constructor argument and branches on it:
`snapshot.LEGACY_CURVE_SOURCE = "BARCHART_STIRF-RL"` selects one unpoliced
`CurvePricer` under `POLICY_NONE` and `legacy_config.CURVE_FOR`, because Barchart
raises on a `snapshot_policy`. `require_lag_telemetry=False`; `_assert_telemetry`
early-returns for an ungoverned source, so no row is flagged for a missing lag it
could never have.

### Sample: 64 days, and how they were chosen

**Not the full 131 days.** The binding constraint was **disk, not time**: `C:` had
7.6 GB free at the start and 1.1 GB at the stop, and a day-run costs 17–32 MB of
`BARCHART_STIRF-RL_CURVE_CACHE` growth. The full window would have needed ~3 GB
that was not there. The sweep carries a hard `--min-free-gb` floor and was stopped
by hand at 1.1 GB rather than by the floor.

The sample is **every 3rd business day of the window, then every 3rd starting one
day later** — a uniform stride-3 calendar sample plus its offset-1 shift, i.e. a
deterministic 2-in-3 design, of which 66 files were written and 64 carry data (the
other two are exchange holidays):

- **64 of the 131 data days (48.9%)**, 2026-01-12 → 2026-07-20, **37,905 units**
- months: Jan 10, Feb 13, Mar 13, Apr 8, May 7, Jun 6, Jul 7 — all seven
  calibration chunks represented
- weekdays: Mon 12, Tue 13, Wed 13, Thu 13, Fri 13 — flat
- population mix matches the persisted table's (T-2): PAID 70.8% / RECEIVED 29.0%
  / UNKNOWN 0.15%; LOW 56.0% / HIGH 35.8% / MEDIUM 8.1%; `curve_suspect_trade`
  33.6%

The measurement is numerically deterministic (§3: the two systems produce the same
number to 8.9e-14), so more days move the agreement figure by nothing. What more
days could add is a *rarer* residue class; the classes found (§5) each recur on
many days, and the smallest is a single row whose cause is named.

The sweep is resumable per day (skip-if-exists, tmp+rename writes), sharded, and
deadline-bounded, so the remaining 67 days are a re-run of the same command once
disk allows.

## 3. The strongest single statement: the two pricing paths are the same number

| path | n | comparison | result |
|---|---:|---|---|
| rate rule | 29,812 | `max abs(s2m_old − dev_new)` | **8.882e-14 bp** (p99 4.97e-14; exactly 0 on 2,840) |
| upfront rule | 8,021 | `max abs(npv_old − npv_new)` | **0.000e+00 USD** |
| upfront rule | 8,021 | `max abs(dv01_old − dv01_new)` | **0.000e+00** |

The residual 8.9e-14 bp is **not** a pricing difference: the mids are identical,
and the two systems associate the multiply differently. `stir_flow` computes
`(traded − mid) * 100`; `conventions.structure_price` computes
`traded*100 − mid*100`. Those differ in the last bits of a double and in nothing
else.

Given that, a side disagreement can only come from a **rule** difference, and rule
differences are enumerable — which is what §5 does.

### Why this beats the 99.59% ceiling, and why that is not suspicious

The brief says the measured ceiling for same-logic reproducibility is 99.59% and
not to expect better. That ceiling was measured **across a stack change** (T-4:
rateslib 2.1.1 → 2.7.1 and the `_v2` → `_v3` tape), and **both** of its two
residuals were stack effects, not logic differences — a `PRICING_ERROR` that the
newer rateslib repairs, and a unit whose `s2m` moved 1.33e-13 → 0.0 into the
missing zero branch.

This tie-out holds the stack fixed. Same process, same rateslib, same tape read,
and the two systems share the **literal curve objects**. So T-4's two residual
classes cannot appear as *disagreements* here — and they don't disappear either;
they reappear as named **strata**: the pricing-error class is `NEW_REFUSED`
(§5.2, where both systems fail identically), and the zero-branch class is
`NEW_EXACT_TIE` (§5.2, 139 rows). 100% on the decisive set is therefore the
expected result of removing the stack variation, not evidence of a vacuous test.
The test that would have been vacuous is one that compared the new code against
itself; §1 documents what was held constant and §5 shows the comparison still
found four distinct behavioural differences.

## 4. `b0` on the legacy curve — an independent reproduction of F-20

The mixture fit was run anyway (only its `b0` is zeroed for the tie-out), so the
fitted per-bucket bias is a free, independent estimate of the thing F-20 measured
with medians:

| bucket | n | fitted `b0` (bp) | `h` (bp) | `s` (bp) | `tau` (bp) |
|---|---:|---:|---:|---:|---:|
| GLOBAL | 29,812 | −0.2828 | 0.0241 | 0.9364 | 9.36 |
| `rate_index=SOFR` | 26,216 | −0.2968 | 0.0205 | 0.8553 | 8.55 |
| SOFR · 6M-1Y | 7,094 | **−0.1508** | 0.0090 | 0.3874 | 3.87 |
| SOFR · 1Y-2Y | 4,460 | **−0.3150** | 0.0207 | 0.7412 | 7.41 |
| SOFR · 2Y-3Y | 5,577 | **−0.4267** | 0.0193 | 0.9413 | 9.41 |
| `rate_index=FED_FUNDS` | 3,596 | −0.1151 | 0.0472 | 1.3376 | 13.38 |

The **monotone tenor gradient is reproduced** (6M-1Y −0.15 → 1Y-2Y −0.32 →
2Y-3Y −0.43), by a maximum-likelihood location estimate rather than a median, on
a different sample. F-20's headline median `s2m` was −0.4836 bp.

This is also why `NEW_ABSTAIN` swallows 11,238 rows: `tau = s²/2h` and the legacy
curve's `s` is ~0.94 bp against an `h` of ~0.02 bp, so `tau ≈ 9.4 bp` and the
dead zone is ±1.9 bp. **The new probability model, handed the legacy curve,
correctly declines to call almost anything** — the abstention is the model saying
the mid is too noisy to resolve a bid-offer of 0.02 bp. Note that on those same
11,238 rows the *point* call still agrees with the old classifier 100% of the
time; abstention changes the confidence, not the side.

## 5. Every disagreement class, with counts and an explanation

### 5.1 The one class that produces disagreements

**`OLD_TICK_RULE` — 5,540 rows, 2,675 disagreements. All 2,675 unrestricted
disagreements in the whole study are here.**

`stir_flow.confidence.score_on_market` routes a print whose `|s2m|` is small
relative to the bucket's dispersion to `apply_tick_rule`, which discards the curve
entirely and takes the sign of the move from the previous print in the same
`(tenor_bucket, kind)`. The new package has **no tick-rule analogue** — it has one
inference rule per unit and a probability, by design. So on those rows the two
systems are answering with different information.

The measured agreement is **51.71%, κ = 0.065** — a coin flip, which is the
correct expectation and is itself evidence: F-20 measured `TICK_RULE` as the one
method that is *balanced* (53/47) because it never touches the curve, while every
curve-using method is 69–78% PAID. Two near-independent labellers on a
78/22-vs-53/47 marginal produce almost exactly this κ. All 5,540 are
`direction_confidence = LOW`.

This is a **scope difference, not a bug**, and LEDGER T-5 already recorded the old
rule's own limits (it can never fire for a package, and it keeps the knife-edge
sign it was invoked to avoid).

### 5.2 Classes where both systems decline (no disagreement possible)

**`NEW_REFUSED` — 72 rows.** All 56 old-`UNKNOWN` rows in the study are in here,
and they are refused by the new code for the *same reason* the old code failed:

| reason | n | old side | explanation |
|---|---:|---|---|
| `UNORIENTABLE_PKG` | 47 | UNKNOWN (47) | PKG-N with 4, 5 or 6 legs under the rate rule. Old flags `ON_MARKET_PKG_N_UNSUPPORTED` and returns UNKNOWN; new raises `conventions.UnorientableUnit`. Same units, same conclusion, better-named. |
| `RISK_IMPLAUSIBLE` | 16 | **RECEIVED (16)** | `fixed_rate` ≥ 100% as a decimal (3.292, 3.402, 3.70, 3.74, 3.776, 4.0 → 329%–400%). See below. |
| `DRIVER_EXCEPTION` | 8 | UNKNOWN (8) | `NonExistentTimeError: 2029-03-11 02:xx`, all on 2026-03-11 — prints stamped in 2029 whose snapped instant lands in the US DST spring-forward gap. Old carries the identical failure as `PRICING_ERROR:2029-03-11 02:18:00`. Both systems fail, identically. |
| `PRICING_ERROR` | 1 | UNKNOWN (1) | `ZeroDivisionError: float division by zero`, unit `1712214265000000101` on 2026-01-13. Old carries `PRICING_ERROR:float division by zero`. Identical failure. |

**The 16 `RISK_IMPLAUSIBLE` rows are the one place the new classifier is
substantively different, and it is right.** `midprice._implausible` refuses field
#31's not-available sentinels before they reach a curve; the old classifier priced
them and returned **RECEIVED on all 16** — a rate 300–400 percentage points above
mid produces a large, confident, meaningless deviation. This is a repair of the
same shape as T-4's `PRICING_ERROR` repair, in the opposite direction.

**`NEW_EXACT_TIE` — 139 rows.** `spread_to_mid_bps` and `deviation_bps` are both
exactly `0.0` (max `|·|` = 0.000e+00 on both sides). The old rule ends
`RECEIVED if s2m > 0 else PAID` with **no zero branch**, so all **139 are labelled
PAID**; `conventions.dealer_side` returns `0` and refuses. This is T-4's class at
scale: 139 rows across 39 of the 64 days, all `direction_confidence = LOW`,
methods `SPREAD_VS_MID` 103 / `FLY_VS_MID` 3 / `NPV_VS_UPFRONT` 1 — overwhelmingly
differentials, where the two legs price off one curve and the difference cancels
to the bit. The new behaviour is correct: at an exact tie the sign of a float is
not evidence.

### 5.3 Residue

**Empty.** Every one of the 37,905 units is accounted for by a named stratum, and
every one of the 2,675 disagreements is `OLD_TICK_RULE`. There is nothing to list
individually.

## 9. Method notes and the things that could have gone wrong

- **The comparator was validated against known answers before it scored anything**
  (`tieout_analyse.py --selftest-only`, 12 checks): κ = 1 on identical labels,
  κ = −1 on total inversion, κ ≈ 0 on an independent relabelling, κ = 0.9793 on
  one planted flip (hand-derived), one planted row per stratum landing in exactly
  that stratum, priority resolving correctly when a row qualifies for several, and
  the `b0 = 0 ⟺ dev > 0` identity. **The self-test caught a wrong expectation on
  first run** — an agreement check asserted 80% where element-wise counting gives
  90% — which is the reason for writing it.
- **Exit code 0 was never taken as success.** Every day's output was checked for
  row counts, and the new pass was checked for zero extra curve builds
  (`seeded_handles == handles_after`) rather than for completing.
- **`snap_instant == snap_timestamp` is asserted, not argued.** The equality
  argument (both floor to the ET minute, decrement one minute, and route through
  `as_intraday_instant`) is checked on every unit at run time.
- **Prod DB.** Reads only, `readonly=True` session, `ensure_schema` never called.
- **Disk.** The sweep grew `C:\...\ARBS\Cache\diskcache\dump\BARCHART_STIRF-RL_CURVE_CACHE`
  to 2,193 MB at 17–32 MB per day-run; `C:` went 7.6 GB → 1.1 GB free. That cache
  is re-derivable and is the reclaimable 2.2 GB if space is needed. `C:` is the
  reason the window is 64 days and not 131.

## 10. What this does and does not establish

**Establishes.** The new `dealer_direction` package, given the old curve, the old
units and the old instants, computes the same deviation to 8.9e-14 bp and reaches
the same side on 100% of every comparable stratum. The direction mapping is not
inverted, under either rule, on any structure. Where the two differ, the reason is
named in every single case, and in the two cases where the new one differs on
purpose — the exact-tie zero branch and the 300–400% "rates" — the new behaviour
is the defensible one.

**Does not establish.** That the new classifier is *right*, only that it
reproduces the old one's logic. The curve effect (§7) says the old labels are
~71% one-way from a curve artefact, so reproducing them faithfully is a
correctness check on the code and not an endorsement of the output. It also says
nothing about the parts of the new package outside this seam — the KRD ladder,
the lineage sidecar, the package-price rule, or the indicator — none of which the
old system has a counterpart for.

**Open.** 67 of the 131 clean days are unmeasured, blocked on disk. The command to
finish them is `scratch/tieout_sweep.sh` with `START=2026-01-14`; every day
already written is skipped.

**And the disk block is one line to remove.** Re-running an already-completed day
still costs 154 s, which means `BARCHART_STIRF-RL_CURVE_CACHE` is never read back
on this path — it is pure write cost. Setting `DiskCacheMixin.CACHE_ROOT` to
`D:\tieout_cache\diskcache` in the driver redirects that growth to `D:` (288 GB
free) at no measured performance cost; it governs the `dump/` cache directories
only, **not** `Caching/curve_store.py`'s base dir, which resolves separately via
`ARBS_CACHE_DIR`/platformdirs and must be left alone — repointing *that* would
turn every warm curve-day into a cold vendor fetch.
