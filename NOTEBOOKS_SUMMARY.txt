KEY CONCEPTS COVERED
================================================================================

CURVES:
  - USD-SOFR-1D: SOFR OIS overnight forwards
  - USD-FEDFUNDS: Federal Funds OIS
  - Multiple sources: CME, ERIS, SDR, WSJ

STRUCTURES:
  - OUTRIGHT: Single instrument
  - CURVE: Two-leg spreads (e.g., 2Y vs 10Y)
  - FLY: Three-leg butterflies (e.g., 2Y/5Y/10Y)

VALUES:
  - RATE: Swap rate/yield
  - NPV: Net present value
  - PV01: Price value of basis point
  - CVX_ADJ: Convexity adjustment
  - MMSS: Mid-market swap spread
  - CARRY_BPS_RUNNING: Carry over horizon

RISK METRICS:
  - Delta/DV01: Rate sensitivity
  - Key Rate Duration: Point-in-time sensitivity
  - Gamma: Convexity risk
  - Vega: Volatility risk

STATISTICAL METHODS:
  - Realized Volatility: Rolling volatility calculation
  - Regression: OLS, TLS, Deming regression
  - Seasonality: Month-end and calendar patterns
  - Interpolation: B-spline, LOESS smoothing

DATA SOURCES & PROVIDERS
================================================================================

CME_NY_EOD_LIVE:
  - Provider: Chicago Mercantile Exchange
  - Type: End-of-day futures and rates
  - Backends: ql_basic (QuantLib), rl_basic (rateslib)

ERIS_EOD_LIVE:
  - Provider: Electronic Regulatory Information System
  - Type: End-of-day OIS curves
  - Coverage: SOFR, Fed Funds

SDR_INTRADAY:
  - Provider: Swap Data Repository via ERIS
  - Type: Intraday swap transaction data
  - Frequency: Multiple updates per day
  - Curve variants: rl_usd_sofr_mtv2_q12x11, rl_usd_ois_stir_q12x12

USTS_FEDINVEST / USTS_WEBULL:
  - Provider: US Treasury data via WSJ/Webull
  - Type: Treasury yields and prices
  - Coverage: On-the-run and off-the-run issues

GSQUANT:
  - Provider: Goldman Sachs
  - Type: Econometric data
  - Used For: Volatility calculations, time series analysis

COMMON CODE PATTERNS

Pattern 1: FETCH CURVE
  from MDP.IRSwaps.IRSwapsMDP import IRSwapsMDP
  mdp = IRSwapsMDP(source="ERIS_EOD_LIVE-RL_BASIC")
  curve = mdp._get_curve(curve_name="USD-SOFR-1D", timestamp="live")

Pattern 2: BUILD QUERY
  from Query.IRSwaps.IRSwapQuery import IRSwapQuery
  q = IRSwapQuery(curve="USD-SOFR-1D", tenor="10Y",
                  structure=IRSwapStructure.OUTRIGHT,
                  value=IRSwapValue.RATE,
                  structure_kwargs={"bpv": 1})

Pattern 3: RESOLVE & PRICE
  pkg, rws = q.resolve_package(pricer_or_curve=curve)
  vmap = q.build_value_map(pricer_or_curve=curve, package=pkg,
                           risk_weights=rws)
  result = vmap.apply(value=IRSwapValue.RATE)

Pattern 4: COLLECT TIMESERIES
  df = tb.get_timeseries(start=date1, end=date2,
                         queries=[q1, q2, q3], n_jobs=8)

Pattern 5: RUN BACKTEST
  strategy = QueryStrategy(name="MyStrategy", triggers=triggers)
  bt = QueryDrivenBacktest(time_grid=tg, mdp=mdp, strategy=strategy)
  bt.run()
  mtm = pd.Series(bt.mtm_history)

================================================================================
KEY FINDINGS ACROSS NOTEBOOKS
================================================================================

CURVES:
- SOFR curve typically 50-100 bps wider than Fed Funds
- Different sources show slight variations in curve shape
- Intraday volatility peaks at European close (3-4 PM NY)

SPREADS:
- Asset swap spreads reveal bond-swap relative value
- Month-end shows predictable seasonality patterns
- Carry metrics useful for trading signals

VOLATILITY:
- Realized volatility clusters around FOMC announcements
- Treasury futures basis varies by contract maturity
- Intraday vol higher in first hours of trading

RISK:
- Key rate duration concentrated at tenor of most exposure
- Fly spreads typically mean-revert
- Risk basis functions decompose portfolio Greeks

SEASONALITY:
- Month-end effects observed in 2Y/5Y/10Y flies
- Consistency varies month-to-month
- Can be exploited for trading strategies

================================================================================
TROUBLESHOOTING REFERENCE
================================================================================

Common Issue: "No data available for timestamp"
  Solution: Check if holiday, verify data source coverage, try nearby date

Common Issue: "NaN in calculation"
  Solution: Clean with dropna(), ffill(), or interpolate()

Common Issue: Slow data collection
  Solution: Increase n_jobs for parallelization, reduce date range

Common Issue: "Connection timeout" from data sources
  Solution: Add retry logic, check network/service availability

Common Issue: "Curve building failed"
  Solution: Check instrument inputs, verify data quality, inspect solver logs
